# 읽기 문서 설계 기준

이 스킬의 목표는 자료를 한 화면에 모으는 것이 아니라, 처음 보는 독자가 원자료의 관계를 다시 조립하지 않아도 맥락을 이해하게 만드는 것이다.

## 완성 기준

문서는 위에서 아래로 다음 질문에 답해야 한다.

1. 이 자료를 읽고 나면 무엇을 알거나 결정할 수 있는가?
2. 결과를 만드는 입력, 판단, 효과는 어떻게 이어지는가?
3. 코드, 정책, 데이터, 외부 문서 중 어떤 근거가 각 설명을 뒷받침하는가?
4. 어디까지 확인했고 무엇은 아직 모르는가?
5. 독자가 먼저 행동하거나 확인할 점은 무엇인가?

원자료 목록만 늘어놓고 독자가 관계를 추론해야 한다면 실패한 문서다.

## 읽는 순서

`sections`는 파일명, 자료 수집 순서, 시간순을 그대로 따르지 않는다. 독자의 질문과 인과 흐름으로 재배열한다.

권장 순서:

- 최종 결과와 결론
- 결과를 만드는 핵심 조건과 변환
- 시스템·조직·외부 서비스 사이의 경계
- 비교, 설정, 데이터, 운영 절차 같은 지원 맥락
- 검증과 남은 질문
- 부록과 참고 자료

핵심 흐름은 `default_open: true`, 부록과 지원 자료는 대개 `false`로 둔다.

## 문장과 제목

- 제목은 내부 카테고리보다 독자의 질문을 표현한다.
  - 나쁨: `서비스 로직`, `기타 자료`
  - 좋음: `요청은 언제 거부되는가`, `운영자가 먼저 확인할 지표`
- section summary는 입력 → 판단 → 결과가 드러나는 1~3문장으로 쓴다.
- 약어와 전문 용어는 처음 등장할 때 풀어 쓴다.
- 한 문단에는 하나의 주장만 둔다.
- 확인한 사실, 해석, 제안, 미확인 사항을 같은 문장에 섞지 않는다.

## 코드 사용

코드는 설명을 장식하기 위한 예시가 아니라 설명의 근거다.

- 원문을 다시 작성하지 말고 확인한 코드를 정확히 인용한다.
- `path`와 `start_line`을 가능하면 기록한다.
- 설명과 직접 연결된 줄만 `highlights`로 강조한다.
- 강조 이유는 발생 조건 → 코드 동작 → 결과 순서의 완전한 문장으로 쓴다.
- 반복, 설정 literal, 준비 코드처럼 첫 독해를 방해하는 부분만 `collapsed_ranges`로 접는다.
- 강조 범위와 접힘 범위를 겹치지 않는다.
- 필요한 일부만 인용했다면 전체 파일을 검토했다는 인상을 주지 않는다.

## 도식

도식은 본문을 장식하는 그림이 아니라 본문과 같은 사실을 말해야 한다. 반대로 말하는 도식은 없는 도식보다 나쁘다.

- 도식을 만들었으면 렌더링해서 반드시 눈으로 확인한다. `validate`와 `compile`은 시각적 정확성을 검사하지 않는다.
- 라벨을 선·노드와 겹치지 않게 배치한다.
- 그룹 경계로 묶은 영역의 소속 노드가 본문 설명과 일치해야 한다.
- 화살표 방향과 연결 순서가 실제 호출·데이터 흐름과 일치해야 한다. 단계를 건너뛰거나 반대로 그리지 않는다.
- 벡터 도식은 위생 처리된 `image/svg+xml` data URI로 내장해 단일 파일을 유지한다.

## 먼저 볼 점

`attention`은 상세 내용보다 먼저 판단할 가치가 있는 항목만 담는다.

- `action`: 지금 해야 할 구체적인 행동
- `caution`: 조건과 영향이 구체적인 위험
- `question`: 답에 따라 결론이 달라지는 질문
- `info`: 본문 전에 알아야 해석이 가능한 전제

취향, 스타일 선호, 막연한 가능성은 넣지 않는다. 해당 사항이 없으면 빈 배열로 둔다.

## 근거와 검증

다음은 서로 다른 근거다.

- 정적 코드·문서 확인
- 로컬 테스트, typecheck, lint, build
- 원격 CI
- merge와 배포
- 실제 런타임 관측

`verification`에는 실제로 확인한 대상 사실만 적는다. HTML 생성 성공이나 JSON 검증 통과는 리포트 대상의 품질 근거가 아니므로 넣지 않는다.

일부 자료를 읽지 못했다면 `metadata`나 `notes`에 부분 범위와 누락 자료를 명시한다. 문제를 찾지 못했다는 사실을 승인이나 안전 보장으로 표현하지 않는다.

## 블록 선택

- `prose`: 결론, 맥락, 인과 설명
- `bullets`: 병렬적인 결과나 기준
- `steps`: 순서가 의미를 갖는 절차
- `code`: 실제 소스와 줄 단위 해설
- `table`: 같은 기준으로 비교 가능한 항목
- `callout`: 본문 흐름 안의 중요한 주의·결론
- `quote`: 원문 표현 자체가 근거인 인용
- `image`: 화면, 구조도, 결과 이미지 (위 도식 기준을 따른다)
- `links`: 추가 탐색용 공식 문서와 원자료

블록 종류가 많다고 좋은 문서가 아니다. 같은 의미를 가장 짧고 분명하게 전달하는 블록 하나를 고른다.
